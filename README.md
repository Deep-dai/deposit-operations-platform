# 存款经营管理台

结构性存款业务界面原型，支持普通产品申报、滚存系列与期次、批量导入、申报查询、复核及发行流程。

## 运行

```sh
python3 -m http.server 4287 --bind 127.0.0.1 --directory dist
```

## 校验

```sh
node --test tests/*.test.js
```

## 发布

GitHub Pages 通过仓库的自动发布流程部署 `dist/`。推送到 `main` 后先运行测试，再发布静态文件；测试文件和本说明不属于网站发布内容。

数据保存在当前浏览器，角色切换只用于交互原型；没有银行后台、真实身份认证或消息发送接口。内置记录为示例数据。本仓库不包含原始业务需求文档、工作表或个人账号配置。

## 发行海报

进入「发行管理」，选择通过一致性校验的产品新建发行，生成材料后打开「发行海报」。

- 单产品海报：选择本次发行中的一只产品，输出 1620 × 2880 像素图片。
- 产品合集：勾选产品并调整顺序，图片宽度 1080 像素，高度随产品数量增加；最多 12 只。
- 固定画面使用用户提供的两张实际海报，原图保存在 `dist/assets/posters/`。品牌标识、主视觉、风险提示、二维码和客服区域直接取自原图；产品信息由 Canvas 重新排版。
- 名称、编号、收益率、期限和日期自动取自通过一致性校验的金市最终要素。空收益率档位不转换成零，保留非零小数精度。
- 挂钩说明默认仅使用挂钩标的，看涨、看跌方向由办理人按说明书补充。风险等级留空不展示，不沿用原图产品的评级。
- 支持 PNG 高清图片和 JPEG 压缩图片下载。调整模板、顺序或补充文字后，原材料确认失效；再次确认下发时保存海报数据快照，已下发版本只读。

这两张模板的固定声明沿用提供的原图，未增加新声明或对其进行合规判断。

Excel 读写使用本地打包的 SheetJS 0.20.3，许可文件位于 `dist/vendor/SheetJS-LICENSE.txt`。

## 发行通知

发行通知采用所提供通知的四节结构：产品发行安排及产品概况、发行渠道、发行区域、营销要点。产品代码、名称及募集日期来自已通过一致性校验的金市回传说明书要素；不从未复核的申报工作副本取数。连续期次可合并标题，非连续产品逐项列出。

- 新发行点击「生成发行材料」；旧草稿需点击「使用通知模板」并确认替换，旧记录不会自动改写。
- 可调整标题、主送单位、落款单位与日期、销售时间、发行渠道、区域、通用附件及固定正文。成文日期由用户填写，不沿用历史通知日期。制度引用为所提供模板的内容，未作现行有效性认定。
- 产品表只读，逐只产品的说明书及风险揭示书自动进入附件清单。通用总协议、风险问卷单独维护；附件清单不表示原件已上传。
- 改动自动保存并清除发行材料确认。来源要素变化、日期缺失、时间关系异常或模板变量未填充时阻止确认和导出。下发时保存通知快照，已下发版本只读。
- 支持真正的 `.docx` 下载，表格跨页重复表头。使用本地打包的 docx 9.6.1（MIT，许可在 `dist/vendor/docx-LICENSE.txt`），不依赖在线转换服务。

当前没有真实金市接口；现支持本地说明书原件识别、核对接收及后续通知生成。原始通知、协议和说明书文件均未加入公开仓库。

## 说明书识别与回传

「发行管理 → 识别说明书」可批量选择文件查看识别结果；「申报详情 → 金市回传」可对当前申报接收资料。支持可提取文字的 PDF 与 `.docx`；旧 `.doc` 需另存为 `.docx` 或 PDF，扫描 PDF 暂不做 OCR。

- 规则按两份实际说明书验证，定位“产品基本要素”及“产品收益率确定方式”，提取名称、代码、募集与存续日期、收益档位、标的、金额等，并保存原文页码、片段及换算说明。不把触发比例当成收益率，不猜未披露的产品结构。
- 产品名称或代码匹配到“金市办理中”的申报后，才可进入回传核对。未匹配文件只展示识别预览，不自动创建申报或完成复核。
- 金市最终值预填复核申报值供经办人按真实回传核对；说明书列单独保留识别值，未识别字段需人工填写，来源标记为人工补充。没有银行接口时不会声称这些预填值来自真实金市系统。
- 接收后进入“待一致性校验”，通过校验后才能加入发行；比较时规范收益率精度、名称空格及起存金额单位，空值不当成零。真实差异继续阻断发行。
- 说明书的购买渠道与通知渠道分别保存。导入原件的通知须核对渠道后才能确认、下载；更改通知渠道或回传来源后，该确认失效。
- 解析使用同源的 PDF.js 5.6.205（Apache-2.0）和 JSZip 3.10.1（MIT），无外部文件上传和转换服务。原件作为 Blob 保存在当前浏览器的 IndexedDB，业务状态保存文件引用及要素依据。切换浏览器不会自动携带原件，JSON业务备份也不包含文件本体。

这是按当前说明书版式实现的规则提取，并非适配所有文档的通用识别器。用户须查看原文及识别结果；版式变化、缺项、多产品混装、复杂收益结构等会要求核对或阻断接收。

## 产品申报入口与待办分工

“结构性存款管理 → 产品申报管理”下保留普通产品申报、滚存产品申报、申报查询三个入口。普通产品申报直接填写或批量导入；滚存产品申报统一承接系列及首期新增、已有系列内产品新增和期次批量导入。系列内新增产品保留为办理页面，不再作为独立菜单。

工作台的“发起产品申报”先选择普通或滚存类型；草稿、退回修改、金市回传、差异处理及复核任务在工作台办理，全部状态与历史在申报查询中查看。旧的 `#period` 列表地址转到滚存产品申报，既有新增、修改和详情地址继续有效。此次仅调整入口与页面组织，不重置浏览器业务记录。

平台标识使用内置生图工具生成的独立几何图形，原始透明 PNG 位于 `dist/assets/brand/operations-mark.png`，同时用于侧栏和浏览器图标。
